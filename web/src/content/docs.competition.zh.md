## 1. 完整项目与统一入口

完整项目从[参赛页](/compete)进入，支持公开 GitHub 仓库链接或不超过 50 MB 的私有 ZIP。语言不限，平台的 Python 运行器负责连接你的程序，不要求项目使用 Python。

平台固定源码版本、启动配置和适配文件，检查通过后由你审阅并确认。适配只提出接口文件，不会悄悄替换你的算法。平台不强制每轮调用模型，但评奖要求至少两个环节采用智能体（大模型驱动）技术，见[规则](/rules)第 3 节。

[最小完整项目示例](https://github.com/BH3GEI/observer-project-example)

入门包也可以直接上传：在入门包目录运行 `python3 pack_agent.py`，生成的 `my-agent.zip` 根目录已带 `observer.project.json`，在「参赛」页选私有 ZIP 上传即可；自带的确定性智能体不需要模型密钥，可用来跑通流程，但它本身不满足评奖的智能体技术要求。

## 2. 启动配置

项目根目录放置 `observer.project.json`，例如：

```json
{
  "schema_version": "observer-project-v1",
  "protocol": "jsonl-v2",
  "image": "python:3.12-slim",
  "working_directory": ".",
  "build": [],
  "run": ["python3", "agent.py"]
}
```

根据语言选择容器镜像和构建命令。`run` 和每条 `build` 命令都使用参数数组（`build` 是命令数组的数组），评测时镜像会固定到具体摘要。不要把密钥写入配置或项目文件。Rust 示例：

```json
{"schema_version": "observer-project-v1", "image": "rust:1-bookworm", "build": [["cargo", "build", "--release"]], "run": ["./target/release/agent"], "environment": {"CARGO_HOME": "/workspace/.cargo"}}
```

**构建与联网：**`build` 命令在程序启动前执行，使用同一个镜像，**可以访问互联网**，因此 pip、npm、cargo 等可以在构建时下载依赖。构建以非 root 用户运行，系统目录只读，时限 10 分钟；只有项目目录（`/workspace`）和 `/tmp`（256 MB）可写，请把依赖装进项目目录：pip 用 `--target .deps` 并设置 `"environment": {"PYTHONPATH": ".deps"}`；npm 设置 `"NPM_CONFIG_CACHE": "/tmp/npm-cache"`（`node_modules` 留在项目里）；cargo 设置 `"CARGO_HOME": "/workspace/.cargo"`。建议提交锁文件，保证每次构建使用相同版本的依赖。

## 3. 每轮请求对应一个决策

项目持续运行，标准输入和标准输出均为每行一个 JSON 对象。日志写到标准错误，响应后立即刷新输出。

- `initialize`：公开配置和目录，不需要回复。
- `decision_request`：本轮快照和 `decision_sequence`，包含当前天气、可观测天区、请求、进度和已经发布的预报。
- `decision_response`：使用相同序号和 `protocol_version: participant-agent-protocol-v2`，返回 `observe` 或 `wait` 决策，可同时附带异常上报。完整结构见下方交互示例。

服务器记录本轮决策后才返回下一轮观测，提前提交未来序号会被拒绝。相同决策可以安全重试，已接受的决策不能替换。未来天气和异常答案保留在服务器。

一个 900 秒日历时隙不一定对应一个决策：曝光可以跨时隙，同一时隙内也可能有多个短曝光。请遵循返回的序号和游标。

### 结束消息 finish

评测结束时（全部时隙完成，或到达总时限），平台会给程序发最后一条消息：

```json
{"protocol_version": "…", "message_type": "finish", "payload": {"termination_reason": "survey_complete", "last_decision_sequence": 1234, "grace_seconds": 30}}
```

- 这条消息不需要回复，之后写到标准输出的内容会被忽略。
- 发出后，平台会关闭程序的标准输入。程序有 30 秒整理数据、写总结，然后应自行退出；30 秒后仍未退出，平台会强制结束它。
- 这 30 秒不计入场景时限，也不影响分数。分数在发出这条消息之前就已经确定。
- 这段时间写到标准错误（stderr）的内容，会保存在结果包的 agent.log 里。
- termination_reason 的取值：survey_complete（全部时隙完成）、global_wallclock_expired（到达总时限）。
- 不认识这条消息的程序照常可用；即使程序因此出错，也不影响成绩。

## 4. 确认版本并评测

平台固定源码版本和启动配置，检查接口后交由你审阅并确认。确认后启动评测，每批运行全部三个正式场景，每次运行逐轮向服务器返回决策，不接受 CSV 上传。

上传和确认版本都不占评测次数（上传每队每天最多 10 次）。还没评测过的版本可以撤回，撤回后不再显示，也不能确认或评测；正在准备的版本要等准备结束后才能撤回。

每点一次「评测此版本」占当天 1 次评测（一个批次）：一次评测把三个正式场景各跑一遍，每个场景运行时限 3600 秒，分数是三个场景的平均分，线上榜取本队最高的一次完整评测。每队每天 10 次。每日次数内可自由评测；请在比赛结束前选定最终版本（见第 6 节）。因平台原因（评测引擎、调度、网络或超时等）失败的评测不计次数，记录中标为「未计入次数」；你的程序构建失败、崩溃或输出不符合协议导致的失败照常计次。再次评测已经评测过的版本需要确认。每日次数按 UTC 0 点（北京时间 8 点）重置，页面显示今天还剩几次。

## 5. 可选的个人模型 API

需要模型时请自备 API 和额度，平台不提供模型额度。不要把密钥放入仓库或 ZIP。

在「参赛」页填写支持 HTTPS 的接口、模型和密钥，并选择处理方式。无论哪种方式，密钥都不进入项目文件、运行结果或日志。

- **不保存（默认）**：密钥只留在你打开的页面里，服务器不保存。每次评测都要保持页面打开直到结束，页面关闭期间的模型调用会失败。**隐藏决赛评测无法使用这种密钥：程序会调用大模型的队伍，须在比赛结束前改为「加密保存」，否则隐藏决赛评测时模型调用会失败。**如果你的队伍进入前列、需要复现核验，核验时也要按主办方约定的时间打开页面配合。
- **加密保存（需主动选择）**：密钥加密保存在服务器上，只在评测和核验时使用，隐藏决赛成绩公布（核实）后自动删除。评测时无需保持页面打开；已保存的密钥可以随时更换或删除。

从「加密保存」改为「不保存」时，服务器上的密钥立即删除。

程序通过环境变量 `OPENAI_BASE_URL` 和 `OPENAI_API_KEY` 调用模型：前者是平台的 OpenAI 兼容代理（chat completions），后者是本次运行的临时凭证，不是你的密钥。代理使用你在本页设置的模型，程序发送的模型名会被替换。

确定性算法不需要密钥，但评奖要求至少两个环节采用智能体技术（规则第 3 节）。解释写得更长不会增加比赛得分。

## 6. 固定场景、最终版本与隐藏决赛

线上赛在三个**固定**的正式场景（A、B、C）上评测。所有队伍、每次评测使用的场景都相同，不按队伍随机生成。场景文件、天气、预报和事件不公开，评测时项目逐步收到观测。得分为[规则](/rules)中定义的总分，批次得分为三个场景的平均值。本队每次评测的结果 ZIP 仍可照常下载。

每批包含全部三个场景，全部完成后才上榜。**线上榜**取每队最高分的完整批次，不能拼接不同批次的场景最高分。榜单实时更新，只用于反馈，**不决定最终排名**。

**最终版本。** 在「参赛」页的「最终版本」栏，队伍任一成员都可以把一个已确认的版本设为本队最终版本，并可在线上赛结束（10 月 7 日 23:59，UTC+8）前更改或取消，之后锁定。若未选择，默认使用本队线上最高分批次的版本。已选为最终版本的版本不能撤回。

**隐藏决赛。** 线上赛结束后，主办方在一个没有人见过的隐藏场景上，对每队的最终版本评测且只评测一次，不占每日评测次数。隐藏场景的数据、运行日志和结果在主办方公布最终成绩前保密，**最终排名只看这个隐藏场景的成绩**。隐藏评测时无人打开页面：**如果你的程序会调用大模型，请在比赛结束前把模型 API 改为「加密保存」，否则最终隐藏场景评测时模型调用会失败。**不调用模型的队伍不受影响。隐藏成绩严格同分时由主办方决定处理方式，并随成绩一起公布。

## 7. 结果与复现

结果包含决策、得分、运行状态及日志，可在「参赛」页下载。隐藏决赛评测的结果在最终成绩公布后才开放。平台的私有复核记录保留源码版本和文件摘要，供主办方重新评分。选手下载内容不包含未来数据和私有密钥。

请保留自己的源码版本、启动配置和复现说明。设计评价根据代码、运行记录和复现进行，与成绩榜分开。
