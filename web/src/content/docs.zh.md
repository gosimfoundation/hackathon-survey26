## 1. 报名与组队

注册后在「找队友」创建队伍，或点击队伍发送加入申请。队长接受后加入；也可向选手发送邀请。双方通过右上角通知查看进度，接收方可以接受或拒绝。每队最多 3 人，个人参赛也需创建队伍。报名、组队、提交和查分都在本站完成，平台自动选择当前比赛，不需要自行辨别阶段。

## 2. 完整项目与统一入口

完整项目从[参赛页](/compete)进入，支持公开 GitHub 仓库链接或不超过 50 MB 的私有 ZIP。语言不限，平台的 Python 运行器负责连接你的程序，不要求项目使用 Python。练习赛和正式比赛使用同一套云端评测流程。

平台固定源码版本、启动配置和适配文件，检查通过后由你审阅并确认。适配只提出接口文件，不会悄悄替换你的算法。平台不强制每轮调用模型，但评奖要求至少两个环节采用智能体（大模型驱动）技术，见[规则](/rules)第 3 节。

[最小完整项目示例](https://github.com/BH3GEI/observer-project-example)

## 3. 启动配置

项目根目录放置 `observer.project.json`，例如：

```json
{
  "schema_version": "observer-project-v1",
  "protocol": "jsonl-v2",
  "image": "python:3.12-slim",
  "working_directory": ".",
  "build": [],
  "run": ["python3", "agent.py"]
}
```

根据语言选择容器镜像和构建命令。`run` 和每条 `build` 命令都使用参数数组（`build` 是命令数组的数组），评测时镜像会固定到具体摘要。不要把密钥写入配置或项目文件。Node.js 示例：`"image": "node:22-slim", "run": ["node", "agent.js"]`。Rust 示例：

```json
{"schema_version": "observer-project-v1", "image": "rust:1-bookworm", "build": [["cargo", "build", "--release"]], "run": ["./target/release/agent"], "environment": {"CARGO_HOME": "/workspace/.cargo"}}
```

**没有 `observer.project.json` 时**，平台会尝试用你在「模型 API」里设置的模型自动生成适配器；没有设置模型或模型调用失败，准备就会失败。入门包 `pack_agent.py` 打出的 ZIP 已经自带这个文件。

**构建与联网：**`build` 命令在程序启动前执行，使用同一个镜像，**可以访问互联网**，因此 pip、npm、cargo 等可以在构建时下载依赖。构建以非 root 用户运行，系统目录只读，时限 10 分钟；只有项目目录（`/workspace`）和 `/tmp`（256 MB）可写，请把依赖装进项目目录：pip 用 `--target .deps` 并设置 `"environment": {"PYTHONPATH": ".deps"}`；npm 设置 `"NPM_CONFIG_CACHE": "/tmp/npm-cache"`（`node_modules` 留在项目里）；cargo 设置 `"CARGO_HOME": "/workspace/.cargo"`。建议提交锁文件，保证每次构建使用相同版本的依赖。

## 4. 每轮请求对应一个决策

项目持续运行，标准输入和标准输出均为每行一个 JSON 对象。日志写到标准错误，响应后立即刷新输出。

- `initialize`：公开配置和目录，不需要回复。
- `decision_request`：本轮快照和 `decision_sequence`，包含当前天气、可观测天区、请求、进度和已经发布的预报。
- `decision_response`：使用相同序号和 `protocol_version: participant-agent-protocol-v2`，返回 `observe` 或 `wait` 决策，可同时附带异常上报。完整结构见下方交互示例。

服务器记录本轮决策后才返回下一轮观测，提前提交未来序号会被拒绝。相同决策可以安全重试，已接受的决策不能替换。未来天气和异常答案保留在服务器。

一个 900 秒日历时隙不一定对应一个决策：曝光可以跨时隙，同一时隙内也可能有多个短曝光。请遵循返回的序号和游标。

### 结束消息 finish

评测结束时（全部时隙完成，或到达总时限），平台会给程序发最后一条消息：

```json
{"protocol_version": "…", "message_type": "finish", "payload": {"termination_reason": "survey_complete", "last_decision_sequence": 1234, "grace_seconds": 30}}
```

- 这条消息不需要回复，之后写到标准输出的内容会被忽略。
- 发出后，平台会关闭程序的标准输入。程序有 30 秒整理数据、写总结，然后应自行退出；30 秒后仍未退出，平台会强制结束它。
- 这 30 秒不计入场景时限，也不影响分数。分数在发出这条消息之前就已经确定。
- 这段时间写到标准错误（stderr）的内容，会保存在结果包的 agent.log 里。
- termination_reason 的取值：survey_complete（全部时隙完成）、global_wallclock_expired（到达总时限）。
- 不认识这条消息的程序照常可用；即使程序因此出错，也不影响成绩。

## 5. 确认版本并评测

平台固定源码版本和启动配置，检查接口后交由你审阅并确认。确认后启动评测，每次运行逐轮向服务器返回决策。

上传和确认版本都不占评测次数（上传每队每天最多 10 次）。还没评测过的版本可以撤回，撤回后不再显示，也不能确认或评测；正在准备的版本要等准备结束后才能撤回。

每点一次「评测此版本」占当天 1 次评测。正式比赛的一次评测在黑客松任务卡 A、B、C、D 上各运行一次，每张卡运行时限 900 秒，分数是四张卡的平均分，线上榜取本队最高的一次完整评测。练习赛的完整项目评测在全部练习卡（α、β、γ、δ）上各运行一次，每张卡同样 900 秒，成绩进单独的练习榜（按卡分别排名）。每天的评测次数以[规则](/rules)页「阶段配置」表和「参赛」页显示的额度为准。每日次数内可自由评测；正式比赛选手请在比赛结束前选定最终版本（见第 8 节）。因平台原因（评测引擎、调度、网络或超时等）失败的评测不计次数，记录中标为「未计入次数」；你的程序构建失败、崩溃或输出不符合协议导致的失败照常计次。再次评测已经评测过的版本需要确认。每日次数按 UTC 0 点（北京时间 8 点）重置，页面显示今天还剩几次。

## 6. 练习赛：本地运行与 decisions.csv

正式比赛开始前（以及整个练习赛期间），可以在本地练习并上传结果文件。

在本地运行：

```sh
python3 local_runner.py --scenario scenarios/dev-reference --agent agent/minimal_agent.py --wallclock 600 --out run_output
python3 score_decisions.py --scenario scenarios/dev-reference --decisions run_output/decisions.csv
```

更短的演示可用 `scenarios/demo-week`。修改 `agent/my_strategy.py` 中的 `choose_action(candidates, snapshot, memory)`，重新运行并比较成绩。算法语言不限；使用自定义程序时，按入门包的标准输入输出协议交换 JSON 消息，普通日志写入标准错误。模型调用可选，确定性基线无需密钥；使用自己的模型服务时，不要把密钥写入结果文件或公开代码。

打开[参赛页](/compete)，选择本地运行的场景，上传 `run_output/decisions.csv`。CSV 列固定为 `decision_id, slot_id, action, tile_id, program, request_id, reason`，文件最大 20 MB，每队每天最多 50 次，以网页额度为准。提交成功后进入详情页，查看评测状态、得分构成、完成情况和回放。练习赛每个场景分别排名，保留本队最高分，榜单只用于练习、不决定奖项。

`config/` 包含规则配置；`outputs/reference/` 包含天区、目标、日历、时隙、天气、预报、事件和观测请求，公开文件可从资源页下载。用入门包在本地运行练习场景时使用 `participant-agent-protocol-v1` 合约；完整项目的云端评测使用 `participant-agent-protocol-v2`（日志里显示的就是这个版本），回答时沿用请求里的 `protocol_version` 即可。入门包自带的智能体两个版本都支持。平台和入门包使用同一评分器，精确公式和常数以场景配置与公开评分器为准。

程序报错时查看输出目录的 `agent.log`；核对场景名称、CSV 列名、文件大小和当天额度，可以用上面的 `score_decisions.py` 命令独立复算。完整命令与字段说明保存在入门包的 `SKILL.md`、`QUICKSTART_ZH.md` 和 `README.md`。

## 7. 可选的个人模型 API

需要模型时请自备 API 和额度，平台不提供模型额度。不要把密钥放入仓库或 ZIP。

在「参赛」页填写支持 HTTPS 的接口、模型和密钥，并选择处理方式。无论哪种方式，密钥都不进入项目文件、运行结果或日志。

- **不保存（默认）**：密钥只留在你打开的页面里，服务器不保存。每次评测都要保持页面打开直到结束，页面关闭期间的模型调用会失败。**隐藏决赛评测无法使用这种密钥：程序会调用大模型的队伍，须在比赛结束前改为「加密保存」，否则隐藏决赛评测时模型调用会失败。**如果你的队伍进入前列、需要复现核验，核验时也要按主办方约定的时间打开页面配合。
- **加密保存（需主动选择）**：密钥加密保存在服务器上，只在评测和核验时使用，隐藏决赛成绩公布（核实）后自动删除。评测时无需保持页面打开；已保存的密钥可以随时更换或删除。

从「加密保存」改为「不保存」时，服务器上的密钥立即删除。

程序通过环境变量 `OPENAI_BASE_URL` 和 `OPENAI_API_KEY` 调用模型：前者是平台的 OpenAI 兼容代理（chat completions），后者是本次运行的临时凭证，不是你的密钥。代理使用你在本页设置的模型，程序发送的模型名会被替换。

确定性算法不需要密钥，但评奖要求至少两个环节采用智能体技术（规则第 3 节）。解释写得更长不会增加比赛得分。

## 8. 固定任务卡、最终版本与隐藏决赛

线上赛在四张**固定**的黑客松任务卡（A、B、C、D）上评测。所有队伍、每次评测使用的卡都相同，不按队伍随机生成。比赛开始时公开[任务卡](/cards)说明和公开输入；天气、预报和事件不公开，评测时项目逐步收到简报和预报。得分为[规则](/rules)中定义的总分，一次评测的得分为四张卡的平均值。本队每次评测的结果 ZIP 仍可照常下载。

每次评测包含全部四张卡，全部完成后才上榜。**线上榜**取每队最高分的完整评测，不能拼接不同评测中各卡的最高分。榜单实时更新，只用于反馈，**不决定最终排名**。

**最终版本。** 在「参赛」页的「最终版本」栏，队伍任一成员都可以把一个已确认的版本设为本队最终版本，并可在线上赛结束（10 月 7 日 23:59，UTC+8）前更改或取消，之后锁定。若未选择，默认使用本队线上最高分评测的版本。已选为最终版本的版本不能撤回。

**隐藏决赛。** 线上赛结束后，主办方在四张没有人见过的隐藏任务卡 E、F、G、H 上，对每队的最终版本评测且只评测一次，不占每日评测次数。隐藏卡的数据、运行日志和结果在主办方公布最终成绩前保密，**最终排名只看 E–H 四张卡的平均成绩**。隐藏评测时无人打开页面：**如果你的程序会调用大模型，请在比赛结束前把模型 API 改为「加密保存」，否则隐藏卡决赛评测时模型调用会失败。**不调用模型的队伍不受影响。隐藏成绩严格同分时由主办方决定处理方式，并随成绩一起公布。

## 9. 结果与复现

结果包含决策、得分、运行状态及日志，可在「参赛」页下载。隐藏决赛评测的结果在最终成绩公布后才开放。平台的私有复核记录保留源码版本和文件摘要，供主办方重新评分。选手下载内容不包含未来数据和私有密钥。

请保留自己的源码版本、启动配置和复现说明。设计评价根据代码、运行记录和复现进行，与成绩榜分开。
